# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use `load skills product-design:get-context` when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

For adapter-governed Product Design builds, keep the agreed project evidence root (it may be this app's parent workspace). Canonical design-qa.json derives design-qa.md there. Rerun and consume review-handoff after implementation changes before claiming completion; do not erase source/capture/history files or infer approval from Markdown. Follow the loaded Product Design executable transition contract.

For peer Product Design workflows, use `load skills product-design:{name}` with the actual Skill name, not sibling SKILL.md reads.
