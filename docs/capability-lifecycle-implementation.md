# Capability-aware lifecycle implementation

## Goal and scope

Connect existing skill workflows to capability facts and durable authorities, not a new task database or agent service. Preserve user-created development `.beads/`, `.entire/`, `.agents/` and existing evidence paths. No automatic setup hooks, installed-plugin updates, production implementation, generation spend, deployment or automatic commits.

## Implementation plan

1. Extend tooling preflight with explicitly supplied current tool schemas: image generation with exact destination support, browser capture/interaction, filesystem and hosting; distinguish available from connectivity/runtime verification. Reuse native Beads/Entire checks.
2. Deliver an explicit read-only product slice reader: confined file/entity/Markdown references, declared blueprint relations, bounded upstream/downstream traversal, source/result hash applicability, optional verified native Beads reads. Mermaid is a derived projection, not an authored graph registry.
3. Deliver a read-only annotation queue inspector: oldest-first validated records, safe route/viewport/bbox, interrupted or duplicate processing diagnostics, no move/edit/capture claim. Existing annotation skill owns actual edits and receipts.
4. Add a shared lifecycle working method to focused skills and canonical rules: retrieve → traverse → explore material uncertainty → verify actual authority/bytes → scoped action and existing fresh transition consume. Link image source preflight and annotation change impact without weakening approvals.
5. Synchronize docs, Mermaid lifecycle and reasoning diagrams, evaluation scenarios and deterministic tests. Run full npm validation/tests, native read-only checks and diff review.

## Ownership and subtraction

Specifications own intended experience and durable reasoning; Beads owns work rationale/dependencies/resolution; Git and optional Entire own development provenance; source ledger and canonical QA own observations. Only references and diagnostics absent from these tools are added. No mandatory project.json/index/relations/tasks/change journal, model/provider configuration, copied transcript or invented authorization. Existing `.gates/` and annotation endpoints remain unchanged; relocation into `.product-design/` is a separately coordinated migration.
