# Product / UX / UI contract

Use for involved exploration, multirole and adaptive/conversational interfaces. Read [product experience method](product-experience-method.md) for the eight-step workflow, discriminating questions, intent/proactivity/native-output contracts and traceability. An experience blueprint is a separate schemaVersion1 artifact validated with validateExperienceBlueprint(blueprint, designContract); legacy design contract v1 is not silently promoted. Reuse answered inputs; do not turn this into a questionnaire. Ask one material blocking question, otherwise state assumptions.

Product: problem, value, shared outcome, evidence and invariants. UX: responsibility, trigger, start/end, information, direct/conversational path, next owner, return and recovery states. UI: principal workspace, hierarchy/density, components, design system, viewport rationale and exact copy. Architecture does not decide user priority. Personas are complementary views, not alternatives. Selected directions and reusable specialized views coexist; do not restart comparison to fill missing screens.

Components declare question, representation, dataKind(metric/calendar/status/artifact), source/version, scope/period/permissions/freshness, detailTarget, action(kind/effect/authorization), states and recovery. A metric additionally defines unit/population/deduplication/zeroVsUnavailable/sameScopeAtDetail. Calendar windows and unknown cost are not KPIs. Read/view/simulation has no effect; preparation is not external send; command needs explicit reviewed version, effect summary and activation.

Known, estimated, unknown, partial and revoked sources differ. Proposed content, saved draft, approved version, authorized command, provider acceptance and proven result differ. Preserve context, manual edits and return after access rechecks; late responses must not take over other pages. Proactive agents may prepare AND execute eligible work under bounded mandates, not invent permission. Review future opportunities as well as exceptions; expose useful prepared work, why-now/lead time, source/unknown timing, attention placement and stop/reconciliation rather than endless per-run approvals. No effects during view navigation.

Compile prompts from task/corpus/copy, hierarchy, primary action/real effect, states, recovery, shell and actually transmitted references. Readable fabricated numbers, versions, dependency arrows or authorization claims are material errors: retain direction but block build source until corrected. Inspection notes do not repair pixels. Review findings bind exact path/hash. Hashes prove identity, not correctness. Structure tests/agent walkthrough are not user research.

validateDesignContract checks declared structure, not business truth or server rights. Shape schemaVersion1: product(problem,value,sharedOutcome,evidenceLevel,invariants[]), personas(id,responsibility), scenarios(personaId,trigger,start,end,successCriterion,directPath,conversationalPath,handoff,states[],recovery), components(id,question,representation,dataKind,source,scope,period,freshness,detailTarget,states[],recovery,action,metric), ui(principalWorkspace,hierarchy,density,designSystem,viewportRationale). Command requires reviewVersion/effectSummary/explicitActivation. Actual source approval uses evidence schemaVersion2 with semantic findings, ordered source hashes and explicit full screen-set approval.
